# kcapk

## Purpose

kcapk is one general Android application builder. It generates the Android
shell, compiles declared native dependencies, packages releases, and preserves
an explicit project boundary for application semantics.

## Architecture

`window.NativeBridge` is the single public root native bridge object.
Android host capabilities are exposed as `window.NativeBridge.<method>` through
the generated facade; the internal host transport and capability token stay
hidden from application code.

Generated common kcapk infrastructure exposes kclibs declared by
`config.json:kclib` directly under `window.NativeBridge`. It discovers their
public functions from the distributed `libNAME.h` headers at build time, and
retains the WebView trusted-origin capability gate before every native
operation.

All Java/JNI bridge sources in `projects/PROJECT/app/` are generated by
`build.sh`; do not add hand-maintained Java or per-function JNI mappings.

## Project contract

Each project provides `config.json` and `assets/`.

`config.json:kclib` declares the complete native dependency set. A project
must not rely on implicit kclibs.

`projects/NAME/config.json` is developer-authored source configuration.
`dist/NAME/manifest.json` is the generated release manifest.

For every declared dependency, `build.sh` resolves these canonical
distribution inputs:

```text
KCLIB_DIST_DIR/NAME.c/aarch64/android/libNAME.so
KCLIB_DIST_DIR/NAME.c/aarch64/android/libNAME.h
KCLIB_DIST_DIR/NAME.c/armv7/android/libNAME.so
KCLIB_DIST_DIR/NAME.c/armv7/android/libNAME.h
```

Each target directory provides the public `libNAME.h` beside its precompiled
library. Kcapk consumes those distributed headers directly; kclib implementation
sources are not required or rebuilt.

## Native packaging

`projects/PROJECT/native/bridge.c` remains available for project-specific
native behavior and is compiled as `libprojectbridge.so`. Ordinary selected
kclib calls do not need project-native code.

The compiled project bridge and declared dependency `.so` files ship in the
APK/AAB native library directories. They are never runtime-updated. An
incompatible native API or ABI change requires rebuilding the affected app.

## Web assets

Web asset provisioning is separate from native packaging. It may keep using
the existing embedded-first, remote-update mechanism where configured.

## Generated output

`projects/PROJECT/app/` is builder output and must not be hand-edited. The
builder owns its generated Java source set and regenerates it deterministically
on every build. Do not edit generated files to change application behavior.

Put deterministic build mechanics in `build.sh`. The generated bridge is the
only JavaScript path for ordinary selected kclib functions.

## Validation

Run builds from `repo/` with:

```sh
./build.sh NAME
```

Do not run broad clean operations or delete generated artifacts unless the
task explicitly requires a narrow, builder-owned cleanup.
